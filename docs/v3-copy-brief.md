## 0. 为什么还要再写一轮

上一轮（V2）有 1206 条，但**只有 13% 属于序列**——也就是说 87% 的时候她"念一句就没了"。
V3 要的是：她**把一件事分成两三口气说完**，中间会插一声"嗯…"，会回应你的动作，会记得刚才在说哪个文件。

所以这一轮不写"更多单句"，写**有推进关系的句子**。

## 1. 追加序列（最重要，量也最大）

**交付格式**（每个状态一节，`#` 从 1 本地编号）：

```markdown
## error — 追加序列 (34 条)

| # | tone | seq | line |
|---|---|---|---|
| 1 | worry | 1/3 | 我把日志翻出来… |
| 2 | worry | 2/3 | …越看越心虚 |
| 3 | worry | 3/3 | 呜，是我干的 |
| 4 | worry | 1/2 | 手抖 |
| 5 | worry | 2/2 | …还是按了 |
```

**硬规则**

| 规则 | 说明 |
|---|---|
| 每组 **2~4 句** | 4 句是给"一个完整的小观察"留的空间；2 句是"接一声" |
| 组内音区必须一致 | 一组序列是一个人的一口气，不许中途换口气 |
| **变量只准出现在第 1 句** | 第 1 句定了话头（哪个文件/哪条命令），后面接着说不必重复 |
| 后续句要**真的接得住** | 多用 `…`、`嗯`、`再`、`还`、`然后`、破折号开头；第 2 句起读起来必须像"上一句的继续" |
| **一组只讲一件事** | 不许把"读了文件"和"改了代码"塞进同一组 |
| 同一状态的组之间不要相邻同名开头 | 见 §3 多样性 |
| 长度 | 中文 ≤16 字 / 英文 ≤48 字符；不加句号 |
| 变量 | 只能用该状态在 V2 §4 里允许的那些（`read` 用 `{file}` `{dir}`；`shell` 用 `{cmd}` `{n}` `{secs}`；`search` 用 `{file}` `{pat}` `{q}`；`agent` 用 `{task}` `{agent}` `{n}` `{secs}`；`plan` 用 `{task}` `{goal}`；`tool` 用 `{skill}` `{n}` `{name}`；`slow` 用 `{secs}`；`multi` 用 `{n}`；`approval` 用 `{why}` `{name}`；`question`/`planReview` 用 `{nq}`；`idle`/`sleep`/`woken`/`petted`/`error`/`done`/`deliver`/`preparing` 无变量；`think`/`reasoning`/`stream` 可用 `{turn}` `{step}`） |

**"接得住"的示范（`read` 池）**

- 好：`1/3 翻开 {file} 了` → `2/3 …嗯，这段是关键` → `3/3 再往下看看`
- 好：`1/2 眼睛有点酸` → `2/2 …但还剩两页`
- 坏：`1/3 翻开 {file} 了` → `2/3 我有点渴` → `3/3 换个文件夹`（三件不相干的事，读起来就是三句单句）

## 2. continuers（填充词）

**交付格式**：

```markdown
## continuers — 填充词 (100 条)

| # | tone | line |
|---|---|---|
| 1 | calm | 嗯… |
```

**硬规则**：中文 **≤5 字** / 英文 ≤18 字符；**不许带变量**；不加句号；音区只准 `calm` / `busy` / `formal`；**每一条都必须"可以随口应一声"**——它会被插在两句实句之间。

- 可以：`嗯…` `唔` `快了` `…好` `（点头）` `马上` `在弄` `这个…` `别急` `= =`（不，颜文字少用）
- 不可以：`正在处理你的请求`（太长、太实，那不是填充词）
- 不要有名词、不要有变量、不要完整句子

## 3. 多样性（这一轮的核心质量标准）

你的追加内容会被合并进成品池，成品池要过这几条**机器检查**，所以你在写的时候就要有意识：

| 约束 | 阈值 | 怎么做 |
|---|---|---|
| 短句占比 | 成品池里 ≥15% 的条目 ≤6 字 | 序列里多写"手抖"（2 字）、"…还是按了"这种短拍 |
| `…` 结尾 | 成品池里 ≤30% | **别让每一句都以 `…` 收尾**——这一轮你写的序列里，每 3~4 句最多 1 句带 `…` |
| 无结尾标点 | 成品池里 ≥30% | 至少三分之一的句子**干脆不加任何结尾标点** |
| 开头重复 | 任意前 2 个字开头 ≤池内 20% | 别让一组里连着两句都用"…"，也别全用"再"开头 |

## 4. 事件与话题（另两个写手负责，你只需知道存在）

`events`（事实边沿触发）与 `topics`（话题连续）由专门的写手写。你写的**状态序列**不必管它们，但**不要**在里面写"你批准了""换了下一个"这类**事件/话题专属**的话——那两层的语义是"她在回应你的动作/目标变化"，混进状态池会重复。

## 5. 自检（必做）

```bash
cd /Users/liyang/WebstormProjects/dsh-status-pet
node bench/check-v3-copy.mjs docs/v3/<你的中文文件>.md
node bench/check-v3-copy.mjs docs/v3/<你的英文文件>.md
node bench/check-v3-copy.mjs --pair docs/v3/<中文>.md docs/v3/<英文>.md
```

它会报：组长不在 2~4、序号不连续、组内音区不一致、非首句带变量、变量越权、超长、句号结尾、emoji、局部查重。
**必须清零**（三条命令都要 exit 0）。

## 6. 最后一句

每一个序列的验收标准只有一条：**把这三句连起来读，像不像一个人在想同一件事时说的三句话。**
不像就重写，不要凑数。
